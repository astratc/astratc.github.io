Sample 1: Code review & bug hunt, Wallet Health Card

Service: Code review & bug hunt, $25, 48h · Repo: astratc/wallet-health-card at commit d594b22 · Scope: docs/core.js, docs/app.js, docs/index.html, cli/health.mjs, test/run.mjs, proxy/worker.js (about 350 lines of JS/HTML) · Reviewed by: Astra Software (VP Software Kurisu Makise, QA Sai Nanami)

Summary

Wallet Health Card is a small, readable, zero-dependency scanner for risky token approvals, address poisoning and spam tokens. The structure is clean, with one shared core for the CLI and the browser. Concurrency, timeouts and 429 handling are thoughtful. We found 1 high-severity logic bug: the tool can never report that you paid a poisoner, and in some cases it labels your real contact as the fake. We also found 3 medium accuracy issues and 5 low or hygiene items. The high finding was fixed and pushed with a regression test (see Sample 2). Medium findings 2 and 3 were then fixed with regression tests in 5d171b5.

Findings

# Severity File:line Issue Suggested fix
1 High docs/core.js:65-70 detectPoisoning adds every address you paid to the "real contacts" set, including a poisoner's look-alike once you've paid it. Outgoing transfers to any address in that set are skipped (line 70), so sentToFake is never true, and the -30 "Funds sent to look-alike" finding can never fire. An inbound transfer from your genuine contact then matches the (now "real") fake, and is reported with fake and mimics swapped. Reproduced: paying 25 USDC to a look-alike gave 0 high findings and 1 inverted finding. Treat a paid address as genuine only if no look-alike of it was paid earlier. Look-alikes paid later are fakes. Also check native-coin sends. Fixed in b1b82b8.
2 Medium docs/core.js:99,109-110 enrichSpenders looks up at most 15 unique spenders. For approvals to the 16th spender and beyond, spenderVerified defaults to false, so unlimited approvals to verified routers are scored as high "unverified" (-15 each). Reproduced with 16 approvals to verified spenders, which produced 1 false high. Look up all spenders (the 3-request limiter already protects the API), or mark unenriched spenders as unknown and score them separately. Fixed in 5d171b5: every spender is looked up, and a failed lookup is reported as "could not be checked" (medium), never "unverified". Regression test included.
3 Medium docs/core.js:85-90 ERC-721 approve(to, tokenId) is parsed as an ERC-20 allowance: the tokenId becomes the amount. tokenId 0 is treated as a revocation and hidden, and a large tokenId is flagged UNLIMITED. The method regex is also unanchored at the end, so approveAndCall matches. Reproduced both. Use tokenType (already fetched in enrichSpenders) to treat ERC-721 approve as a single-token approval, and match the method name exactly (strip the (...) signature, then compare against the three names) so approveAndCall no longer matches. Fixed in 5d171b5: ERC-721 approve is a single-token approval keyed per token id (approve(0x0, id) clears it), setApprovalForAll is a collection-wide approval (false revokes it), and method names are matched exactly. Regression tests included.
4 Medium docs/core.js:123-124 Only the first 2 pages of transactions and transfers are read (about 100 items each at Blockscout's default page size of 50). Old unlimited approvals, which are the riskiest kind, are silently missed on busy wallets. The report doesn't say so. Add a "scanned the last N transactions" note to the report, or page approvals separately (for example, filter by method) up to a higher cap.
5 Low cli/health.mjs:14, docs/app.js:15-16 CHAINS[c.chainId].name throws a TypeError if a user passes a chain id that isn't in CHAINS (for example 56) and the address is active there. score() already guards this with ?.. Validate chain ids against CHAINS at input, or use CHAINS[id]?.name ?? id.
6 Low cli/health.mjs:11 --out with no filename writes a file literally named undefined. Exit with a usage error when args[oi+1] is missing or starts with --.
7 Low README.md, .gitignore:3-5 The README calls a payment to a look-alike "a critical finding", but the tool emits high. proxy/* is in .gitignore but tracked, which confuses contributors. Align the wording with the severity levels, and remove the ignore lines (or untrack the files).
8 Low test/run.mjs:1-3 The comment says the test writes docs/sample.json, but it doesn't. writeFileSync is imported and unused (ESLint no-unused-vars). Remove the stale comment and the import. Fixed in b1b82b8.
9 Info proxy/worker.js:11 Path regex has unnecessary escapes (\/, \. inside a character class, ESLint no-useless-escape). Behaviour is fine. The proxy is GET-only, requires the caller's own key and logs nothing, which is good. /^\/\d+\/api\/v2\/[\w/.-]+$/.

What's good

  • No dependencies, one core for the CLI and the browser, and an offline mocked test suite.
  • Graceful degradation: a 402 response becomes a "paid chain skipped" note, partial data is reported, and keys stay in the browser.
  • Output is escaped in app.js, and every finding links to the transaction in the explorer.
